## Configuración que debe confirmar operación

| Área | Configuración / prueba de salida |
| --- | --- |
| Orders | En el archivo de entorno privado de API: `CAMBA_MP_CHECKOUT_ORDERS=true`, `MERCADOPAGO_ACCESS_TOKEN`, `CAMBA_MP_COLLECTOR_ID`, `CAMBA_MP_WEBHOOK_SECRET` y `CAMBA_MP_LIVE`. Confirmar que el vendedor y las credenciales correspondan al mismo entorno y a Uruguay. No usar `CAMBA_MP_LIVE=true` para ensayos. Definir `CAMBA_APP_URL` con el origen HTTPS de la tienda, y configurar el evento Order hacia `POST /api/v1/webhooks/mercadopago` en ese origen. Conservar Preferences para intentos anteriores. |
| Evidencia de Orders | Aprobado y rechazado deben mostrar ID de orden, ID/estado de la transacción, recepción firmada y estado aplicado al mismo pedido. `created` o `recover` sin transacción no son evidencia de cobro. Registrar hora y `x-request-id` si vuelve a ocurrir. |
| Venta en línea | El Compose de producción usa `CAMBA_CHECKOUT_REQUIRE_ONLINE_PAYMENT=true` por defecto. Sin pasarela efectiva rechaza una compra nueva con 503 sin reservar stock. Cambiar esta política solo si Camba aprueba otro medio de pago. |
| Edge | Configurar `CAMBA_TRUSTED_PROXY_IPS` con las IP exactas y estables de los pares ingress; no usar comodines ni rangos. El borde debe mantener el Host validado y sobrescribir `X-Forwarded-For`, `X-Forwarded-Proto` y `X-Forwarded-Port` con la IP, esquema y puerto públicos reales. El Nginx de FastCGI normaliza Host y quita el puerto; sin el puerto confiable fallan las firmas en puertos HTTPS no estándar. Verificar los límites por IP y los enlaces firmados antes de liberar. |
| Resend | En el mismo archivo privado `CAMBA_API_ENV_FILE` de `api-fpm`, `worker` y `scheduler`: `MAIL_MAILER=resend`, `RESEND_API_KEY` y `MAIL_FROM_ADDRESS` del dominio verificado. No imprimir el cache de Laravel ni renderizar Compose con valores reales en la salida. Probar aceptación y recepción por separado con destinatario autorizado. Dev y CI conservan Mailpit o el mailer de prueba. |
